# NVK Agent v0.1.9 — Orb Life (flare, auto-orbit, halo)

**Date:** 2026-11-22 · **Status:** built + verified, NOT deployed (live is v0.1.8)
**Owner direction:** "port the flare, auto-orbit and halo into our orb" (2026-11-22 ~22:43 PT)

## Reference

NvK's original Codex Orb System (WebSim,
https://websim.com/@grandnectar29356979/web3d-codex-orb-system-3;
browser look 2026-11-22 22:38–22:41 PT): a speckled cyan sphere in a
green/cyan particle halo that slowly pulses and periodically FLARES
white-hot with a strong blue glow, then settles back to cyan; a ring
of 7 nodes that drifts/orbits on its own; drag-to-rotate; rotating
poetic quotes. The original has NO function (clicks do nothing, nodes
open nothing) — we keep our function and port only its LIFE.

## What was ported (all three, honestly)

### 1. Flare — DONE
- Fires on a REAL pipeline completion only: a `'result'` stage event
  (the one transition that maps the orb to `'complete'`).
  `shouldFlareOnStageEvent()` in `src/experience/orb/orb-life.ts`.
- The host (`OrbHost.tsx`) counts completions (`flareSignal`, +1 per
  `'result'` event) and passes the count to the renderer.
- The renderer (`CodexOrbSystem.tsx`) turns each signal edge into an
  intensity of 1.0 and decays it exponentially (half-life 0.8 s, real
  seconds from the frame delta). The shader (`uFlare` uniform) mixes
  the orb toward white-hot (`flareWhite`, 0.85/0.95/1.0) and the core
  swells slightly (+0.12 scale at full flare).
- NO timer anywhere on this path (tested). The decay is a frame-delta
  function, like the existing click-impulse spring. The orb STATE
  never moves on decay — only the glow.

### 2. Auto-orbit — DONE
- The node ring OSCILLATES ±20° inside the v0.1.8 front arc
  (`node-layout.ts`: `nodeOrbitOffset`, amplitude 20°, angular speed
  0.06 rad/s, period ~105 s). Effective arc breathes between 15° and
  165°; every node stays z > 0 at all times (swept and asserted in
  tests over two full periods).
- Applied as an ABSOLUTE group rotation (`rotation.y =
  nodeOrbitOffset(elapsedTime)`), never an increment — the arc can
  never wind into a revolution. The original's full revolution (which
  hides panels behind the sphere and washes out their text) is
  deliberately NOT copied.
- All four labels stay visible at once (the v0.1.8 requirement).

### 3. Halo — DONE
- A particle shell (600 points desktop / 250 mobile) at radius
  5.5–7.0, just outside the core (radius 5), inside the node ring
  (radius 12). Built in the SAME particle effect as the mode
  particles (same group, same cleanup, same vertex-color
  post-processing) — an added layer of the one particle system, not
  a second system. Tagged `userData.isHalo`.
- Color is the REAL orb state (lerped like the orb's `uColor`, same
  target, same rate): idle cyan, thinking purple, executing green,
  blocked red — the Phase A vocabulary. Per-particle colors are
  brightness texture only (0.75–1.0 white), so the state color
  multiplies cleanly.
- Opacity/size breathe with entropy and brighten/swell on a flare
  (`haloOpacityFor` / `haloSizeFor`, pure helpers in `orb-life.ts`).

### NOT ported — rotating poetic quotes
The original's rotating quotes are canned decoration. No quote
machinery was added anywhere (tested: no `quote` in the orb files'
code). If a line of text ever appears on the orb it must be a real
status line from the pipeline.
